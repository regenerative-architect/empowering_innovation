SHARED ARCHITECTURE

One protocol, independent implementations

Guide · protocol and dependency map

What: A common record grammar, design contract, and map of cross-domain dependencies. How: Inspect the interfaces before adapting another module. Keep scope-specific data local, obtain consent for sharing and document all transformations. Outcome: Future implementations can exchange compatible data without sharing accounts or creating a single central authority.

Lifecycle: six auditable states

Do not confuse a completed task with an achieved outcome. Progress badges reflect documentation. Outcome claims require measured data, appropriate comparison and review.

Interoperability contract

  1. Identity: local random record ID; no universal person identifier.
  2. Provenance: source URL, date and evidence category.
  3. Semantics: metric name, definition, unit and direction of improvement.
  4. Consent: sharing is opt-in, scoped, revocable before transfer.
  5. Uncertainty: observation, estimate and causal inference remain distinct.
  6. Portability: schema version and JSON import/export.
  7. Failure: contradictory results and harms are preserved.
